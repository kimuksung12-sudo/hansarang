# 한마음 · 케어플랜 체크 - Firebase 직원 로그인

지금 구현된 것: Firebase **이메일+비밀번호 인증**, Firestore **직원 승인 확인**, 직원 전용 업무 홈, 로그아웃, 아이디(이메일) 기억하기. 회원가입 버튼이 없으며, **기존 이메일/비밀번호를 Firebase에서 발급**합니다.

> 필수: Firebase 프로젝트를 만든 뒤 아래의 설정을 직접 마쳐야 작동합니다. Firebase 프로젝트의 실제 설정값이 없으므로 파일만 내려받아서는 계정 인증이 실행되지 않습니다.

## 1. Firebase 프로젝트 생성

1. https://console.firebase.google.com/ 에 접속합니다.
2. '프로젝트 추가'에서 `careplan-checker`처럼 **영문 프로젝트 이름**으로 만듭니다. 프로젝트 ID는 콘솔에서 확인합니다.
3. 프로젝트 홈에서 **웹 앱(`</>`) 추가**를 누르고 앱 이름을 입력해 등록합니다.
4. 콘솔의 '프로젝트 설정 → 내 앱 → SDK 설정 및 구성 → 구성'에서 `firebaseConfig`를 확인합니다.

## 2. 연결 설정

`js/firebase-config.js`를 열고 다음 네 항목에 실제 값을 넣습니다.

```js
export const firebaseConfig = {
  apiKey: "AIza...",
  authDomain: "실제-프로젝트-ID.firebaseapp.com",
  projectId: "실제-프로젝트-ID",
  appId: "1:숫자:web:문자열"
};
```

`apiKey`, `authDomain`, `projectId`, `appId`는 Firebase에서 제공하는 **웹 앱 설정값**입니다. 실제 비밀번호나 Firebase Admin 서비스 계정 키는 이 파일에 넣지 마세요.

## 3. Firebase Authentication 활성화

1. Firebase 콘솔의 **빌드/보안 → Authentication → 시작하기**를 엽니다.
2. **Sign-in method → 이메일/비밀번호 → 사용 설정 → 저장**을 누릅니다.
3. **Users → 사용자 추가**에서 직원용 이메일과 비밀번호를 생성합니다.
4. 비밀번호를 직원에게 전달할 때는 안전한 방법으로 개별 전달하고, 직원별 고유 계정을 사용하세요.

**주의:** 이메일+비밀번호 제공자를 활성화하면 웹 앱의 가입 버튼을 없애더라도 API를 통해 임의 가입을 요청할 수 있습니다. 이 샘플은 **Firestore 직원 승인 명단**에 등록된 UID만 업무 홈으로 이동할 수 있도록 추가로 제한합니다. 향후 환자 데이터도 반드시 별도 보안 규칙으로 보호해야 합니다.

## 4. Firestore 승인 명단 만들기 (필수)

1. Firebase 콘솔에서 **Firestore Database → 데이터베이스 만들기**를 선택합니다. 리전을 선택하고 프로덕션 모드로 시작해도 됩니다.
2. **규칙** 탭에 이 프로젝트의 `firestore.rules` 파일 내용을 붙여 넣은 뒤 **게시**합니다.
3. **Authentication → Users**에서 만든 직원 계정의 **사용자 UID**를 복사합니다.
4. Firestore의 **데이터** 탭에서 컬렉션 `staff`를 만들고, **문서 ID는 직원의 UID와 정확히 동일하게** 지정합니다.
5. 아래 필드를 추가합니다.

| 필드 | 유형 | 예시 |
|---|---|---|
| `active` | boolean | `true` |
| `name` | string | `홍길동` |
| `role` | string | `social_worker` |

직원이 퇴사하거나 접근을 중지하려면 `active`를 `false`로 변경하고 Authentication에서도 계정을 사용 중지하세요.

## 5. 로그인 페이지 실행

`<script type="module">`을 사용하므로 예전처럼 HTML을 바로 더블클릭하는 `file://` 방식 대신 로컬 웹 서버 또는 Firebase Hosting에서 실행해야 합니다.

- Windows: 이 폴더에서 터미널(PowerShell 또는 명령 프롬프트)을 연 다음 `py -m http.server 5500` 입력 (Python이 설치된 경우).
- 브라우저에서 `http://localhost:5500` 접속.
- Firebase Authentication → Settings → Authorized domains에서 테스트가 필요하다면 `localhost`를 추가합니다. 2025-04-28 이후 생성한 프로젝트에는 기본 추가되지 않습니다.
- 실제 직원 사용 시에는 Firebase Hosting 등 **HTTPS 사이트**에 배포하세요.

## 보안 및 범위

- 직원별 비밀번호는 Firebase Authentication이 확인합니다. 자바스크립트 코드나 localStorage에는 비밀번호를 저장하지 않습니다.
- 인증 세션은 `browserSessionPersistence`로 탭/창 세션 동안만 유지합니다. 공용 PC에서는 꼭 로그아웃하세요.
- 현재 `dashboard.html`은 **계정 연결 확인용 화면**입니다. 엑셀 분석, 환자정보 저장/전송, 권한별 서비스 접근 통제는 아직 구현되지 않았습니다.
- 클라이언트의 화면 이동 제한만으로 데이터가 보호되지는 않습니다. 모든 향후 Firestore/Storage/Cloud Functions 데이터 접근을 **서버측 보안 규칙/권한 검사**로 통제해야 합니다.
- 장기요양계획서 및 케어포 자료에는 민감한 개인정보가 포함될 수 있으므로 실사용 전 접근권한, 암호화, 저장기간, 감사로그, 개인정보 처리 위탁 관련 법적 요구사항을 검토하세요.
- Firebase SDK는 13.3.0 CDN 모듈을 사용하므로 개발 중 인터넷 연결이 필요합니다.


## 연결 완료된 Firebase 웹 설정
이 배포본에는 hansarang-cdbd2 웹 앱 설정이 반영되어 있습니다. GitHub Pages 저장소의 루트에 index.html, dashboard.html, css/, js/, assets/를 업로드하세요. Firebase Authentication > 설정 > 승인된 도메인에서 GitHub Pages 도메인(예: 사용자이름.github.io)을 확인하세요. Firebase Authentication의 이메일/비밀번호 공급자를 활성화하고, Firestore Database를 생성하여 firestore.rules를 게시하고 staff/{직원 UID} 문서에 active=true, name, role을 등록해야 로그인 후 업무 홈에 접근할 수 있습니다. 로그인 페이지 인증만으로 장기요양 개인정보 접근 권한이 보장되는 것은 아닙니다.


## 달력 첫 화면
로그인 및 Firestore 직원 승인 확인 후 dashboard.html에서 현재 월 달력을 표시합니다. 이전/다음 달, 오늘, 날짜 선택 기능을 제공합니다. 일정은 아직 저장되지 않으며 Firebase에 일정 데이터를 기록하지 않습니다.


## 폴더 경로 변경 사항
로그인 페이지는 루트 `index.html`, 로그인 후 달력 페이지는 `html/dashboard.html`입니다. 로그인 성공 시 `./html/dashboard.html`로 이동하며, 달력에서 로그아웃/미승인 시 `../index.html`로 이동합니다. 달력 페이지의 CSS/JS/로고 경로는 `../css/`, `../js/`, `../assets/`를 사용합니다.

- 현재 제공 기능은 수동 입력/검색/수정/삭제입니다. 업로드된 .xls 자동 추출은 구현하지 않았습니다.
- 운영 전 개인정보 처리 및 보안 점검, 역할 권한, 접근 기록, 삭제·백업 정책을 검토하세요.


## 장기요양 필요내용 추출 범위 변경
엑셀의 `장기요양 필요내용` 열을 찾아 해당 열의 항목 전체를 대상으로 추출합니다. `필요영역`, `세부제공내용`, `작성자명`은 가져오지 않습니다. 열 제목을 찾지 못하면 타 열을 추측하지 않고 경고합니다. 추출 결과에서 모든 항목을 확인한 후 Firebase에 저장해야 합니다. 기존 Firestore 필드 `needs`와 보안 규칙은 변경하지 않았습니다.


## 제공계획서 적용기간 수정
`장기요양급여 제공계획서 적용기간`이라는 머리글에 대응하는 날짜 범위만 자동 추출합니다. `장기요양급여 계약기간`, `장기요양급여 계약일` 등의 값은 자동으로 대입하지 않습니다. 예시 사진에서는 `2026-01-20`~`2026-11-13`이 맞습니다. 날짜를 못 찾으면 공란으로 두고 원본 확인을 요청합니다.


## 장기요양 필요내용별 횟수 추가
엑셀의 `장기요양 필요내용` 및 같은 행 `횟수` 열을 찾아 `일 1회`, `주 2회` 같은 값을 추출합니다. 화면에서 각 항목별 횟수를 확인·수정한 후 저장합니다. Firestore에 기존 `needs` 외에 `needDetails` 배열(각 `{text, frequency}`)을 추가하므로 반드시 함께 제공된 `firestore.rules`를 Firebase 콘솔에 게시해야 저장이 가능합니다. 종합의견의 `주 N회`는 종전대로 별도 필드에 보관합니다. 병합 셀/여러 줄 셀에서 빈 횟수는 추정하지 않고 수동 확인을 요청합니다.

## 항목별 횟수 추출 수정
- 숫자형 `일 1회`, `일 5회`, `주 2회`와 조건형 `필요시`, `수시`, `상시`, `매회`를 인식합니다.
- 필요내용-횟수를 행별로 짝지어 표시하고, 빈 횟수는 `⚠ 횟수 미확인`으로 강조합니다.
- 미확인 항목 이름과 개수, 인식하지 못한 횟수 원문도 경고로 표시합니다.
- 시트 구조에 따라 셀이 나뉜 경우 자동 추출이 누락될 수 있으므로 저장 전 실제 엑셀과 대조하세요.
- Firestore 데이터 구조 및 규칙 변경은 필요하지 않습니다.


## 병합된 횟수 셀 추출 개선
케어포 XLS/XLSX의 실제 병합 영역(`!merges`) 좌표를 기준으로, `횟수` 열의 병합 셀에 속한 각 `장기요양 필요내용` 행에 동일한 횟수를 부여합니다.
예: `적절한 수분 섭취`, `균형잡힌 식단 관리` 두 행에 걸쳐 `일 2회`가 병합되어 있으면 두 항목 모두 `일 2회`를 추출합니다.
병합 영역 정보가 없는 빈 셀은 임의로 직전 값을 복사하지 않으며 `횟수 미확인`으로 표시합니다. 저장 전 확인해야 합니다.
기존 Firebase 문서 형식(`needDetails`)과 보안 규칙은 변경되지 않았습니다.


## 종합의견 괄호 3종 분리 추출
`개인별장기요양이용계획서` 표현 이후, `주 N회`가 들어간 괄호를 순서대로 인식합니다.
- 첫 번째: 개인별장기요양이용계획서 권장시간 (`recommendedSchedule`)
- 두 번째: 평일 적용 수가 (`weekdaySchedule`)
- 세 번째: 토요일 적용 수가 (`saturdaySchedule`) — 없으면 빈 문자열
괄호 뒤의 `10시간 미만` 등 상한도 연결하여 저장합니다. 기존 `weeklyCount`는 첫 번째 괄호의 주당 횟수를 기록합니다. 각 항목은 수동 확인 및 수정 가능합니다.
**Firebase 콘솔 Firestore → 규칙에서 새 `firestore.rules` 전체를 게시해야 저장됩니다.**


### UI 단순화 (권장 주당 횟수 제거)
계획서 등록 화면의 `권장 주당 횟수 (숫자)` 및 `횟수 단위` 입력을 제거했습니다. 계획서 목록에서도 독립된 주당 횟수 열을 제거했습니다. ① 이용계획서 권장 시간 ② 평일 수가 ③ 토요일 수가만 사용하며, 항목별 필요내용 횟수 입력은 유지됩니다. 새 문서 저장 시 `weeklyCount`, `weeklyUnit` 필드를 보내지 않습니다. 기존 저장 문서의 해당 레거시 필드는 삭제하지 않습니다. **새 `firestore.rules`를 Firebase 콘솔에 게시해야 신규 등록이 됩니다.**


## 종합의견의 괄호 없는 서술형 문장 지원
- 기존 `(주5회 8시간이상) 10시간 미만` 형식과 괄호 없는 `주 2회 8시간이상 10시간 미만` 모두 인식합니다.
- 처음 발견된 주당 횟수+시간 구간은 **개인별 이용계획서 권장**, 다음은 **평일 실제 적용 수가**, 세 번째는 **토요일 실제 적용 수가**입니다.
- 세 번째 구간이 없으면 토요일은 공란으로 남깁니다.
- 일치하는 시간 구간을 찾지 못하거나 시간 상한을 찾지 못하면 검토 경고를 표시합니다.
- Firebase 저장 필드는 변경하지 않았으므로 보안 규칙을 수정할 필요가 없습니다.


## 토요일 적용 수가 미기재 표시
토요일 적용 수가가 비어있으면 예시 문구를 보여주지 않고, 주황 배경의 `토요일 적용 수가 없음 (원문에 미기재)` 안내를 표시합니다. 값이 들어오면 안내는 사라집니다. 기존 Firebase 필드 및 보안 규칙은 변경되지 않았습니다.
